1. 绿色版目录里调 python 一律加 `-B`；**语法检查用 `ast.parse`，别用 `py_compile`**。
2. 跑全量前确认 `_dev/.mutation.lock/` 不存在；**别人持锁时不跑不下结论**。
3. **测试断言不许依赖机器速度**（注入固定成本/调用次数 → 断言结构性事实）。
4. **契约双向覆盖**；**不许放宽任何既有断言**。
5. 定版前对着**出货修订**整批复跑全部证据；SPEC-BAD / ANCHOR-LOST / NOT CAUGHT / WRONG TEST **一律不许当通过**。

## 本轮两条设计原则（用户明确反馈后的修正）

1. **HCI 原则是约束，不是理由**：任何"按原则"的改动，**必须先用"用户实际路径能不能走通、会不会被打断"验一遍**。本轮凡是"加确认/加回执/加提示"的，**先问：这一步会不会让熟路多一步？会不会覆盖掉用户刚看的东西？**
2. **回执的载体要分场景**：**列表内的连续操作**（加/删步骤等）**用窗口内联状态行**（同仓正例 `RoleImportDialog._on_add_form` 的 `self._notes.setText`），**不要用宠物气泡**（单窗口覆盖式、无队列、滞留 5 秒）。气泡只用于"一次动作一句、且用户会看宠物"的场合。

## 代理 A · 对话框与交互（`pet_dialogs.py`）

**领地**：`pet_dialogs.py`、`tests/test_dialogs_feedback_v280.py`、新建 `tests/test_dialogs_behavior_v290.py`。

### A1【P0】行为步骤的「动作」改**可选可输入下拉**
现状：`_param` 是裸 `QLineEdit`，**用户只能手打动作名**，全仓没有动作选择器。
**做**：改成**可编辑下拉**（`setEditable(True)`），候选来自 **B 提供的接口**（见 B1：`custom_actions() ∪ ANIM_ACTIONS ∪ jump/emote`）；手填仍允许（老行为文件里可能有别的名字）。
**验收**：① 下拉里能看到候选 ② 手填一个不在候选里的名字仍能保存 ③ 老行为文件（含任意动作名）读入后**原样显示与保存**（不许因为下拉把未知名字吃掉）。**变异**：把候选来源换成空列表 → 第一条必须红。

### A2【P0】行为设置内加「**＋导入图片做动作…**」
现状：从素材做动作在**另一个对话框**（`RoleEditDialog`，且只对自定义角色开放）。
**做**：在行为设置里就地加一个入口；**抽公共函数复用 `RoleEditDialog._add_frame_action` 的逻辑**（B 负责把该逻辑抽成可复用函数，见 B2；你负责接 UI）。
**验收**：① 从行为设置能走完"选图 → 命名 → 出现在动作候选里" ② **取消是干净的**（不产生半截动作） ③ 成功后**给回执**（这次用**内联状态行**，不用气泡）。

### A3【P0】行为步骤补**上移 / 下移**
现状：**没有上移下移**，而标签写着"按顺序执行"。
**做**：补两个按钮 + **到顶/到底给回执**（照 `LinesDialog._move_line` 的做法）**+ 选中项跟随移动后仍选中**。

### A4【P1】回执载体改造：**行为「添加/删除步骤」改内联状态行**
现状实测：**一个 5 步行为弹 7 条气泡**；气泡覆盖式、连点只有最后一条可见且滞留 5 秒。
**做**：把那一组的回执改成窗口内**状态行**（同仓正例 `RoleImportDialog._add_form`）。**保留**"一次动作一句"的整体口径，但**列表内连续操作不要再弹气泡**。

### A5【P1】「关闭」改**取消 + 未保存确认**
现状实测：**未保存草稿静默丢弃**（warn/info/confirm 全空）。
**做**：有未保存改动时确认；无改动直接关。**注意原则 1**：不要给"没有改动"的常规关闭加一步。

### A6【P1】复盘**删自定义动作的二次确认**（与上一轮方向相反）
现状：它自己的文案写着"这一步只是暂存…取消会放弃全部改动"——**给可撤销操作套了不可逆确认**。同仓反例：导入向导删形态行同为暂存态**不加**确认。
**做**：**去掉那个确认**（或改成轻量提示）；**同步改掉上一轮那条断言**（**必须是加强式改写**：改成断言"删掉后可取消恢复"，不是把断言删掉）。**并在回报里写明这是有意撤销上一轮的一个决定**。

### A7【P1】「导入…」改名 + 非 JSON 给人话
现状：文件过滤器写死 `行为 JSON (*.json)`（`:2975`），把 PNG 丢进去 → **原始英文异常**（utf-8 解码失败）。
**做**：按钮文案改「**导入行为文件（.json）…**」；非 JSON **给人话原因**（不要抛原始异常）。

### A8【P1】统一提交模型（**按 B3 给定的清单执行**）
现状：**7 个对话框"保存即关窗"** vs **2 个"保存不关窗"**（`BehaviorDialog` / `AlarmDialog`）。

现状实测：**169 个按钮只有 12 个有 tooltip（7.1%）**；而"**点保存才落盘**"这条**决定成败**的信息**只写在 tooltip 里**。

### B4【P0】`idle_actions` 清理**死分支**

### B5【P0】待机下拉与配置**一致**
现状实测：配置里有 **2 条**待机动作时，下拉显示 **（不启用 → 默认待机）**；**点一下 → `idle_actions` 2 条变 1 条 + `idle_play_mode` 改 single**，只有一句通用气泡。**这是数据损失面。**
**做**：下拉状态**由配置推导**（不是硬编码"不启用"）；**改变模式不许静默丢条目**（要么保留、要么明确告知并给撤销/确认）。**验收**：造"2 条 + sequential"的配置 → 下拉显示正确；**任何一次下拉操作后条目数不减少**（除非用户明确选择丢弃，且有确认）。

### B6【P1】「试播」在保存失败时**不许播旧内容**
现状实测：**保存失败时仍然 `_run_behavior`** → 播的是旧内容，用户以为在试播自己的修改。
**做**：保存失败 → **不播**，并明确告知原因（状态行）；成功 → 播。**变异**：恢复"失败也播" → 必须红。
