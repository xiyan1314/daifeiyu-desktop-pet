## 1. 做了什么（对着任务书 A1~A4）

### A1 `pet_plugin_index.py`（新建，**701 行**，Qt-free）

> 行数是**实测**（v2.6.0 第 4 轮定稿时数，与上面表格同一时点）：原稿写 501 行，落笔后又长了 —— 远端路径硬化
> （P2-a 只收 https / P2-b 跨信任域 / P3-2 ".." 段 / P3-3 file:// 折本机路径）、体积上限前置
> （P2-c）、以及本轮新增的 3 处静默 except 登记，都在这个文件里。
* **注入式取数**：`fetch(url) -> (bytes | None, err)`，缺省 `default_fetch`（远端 urllib 分块读 +
  进度回调；本地路径直接读文件）。**远端才走注入的 fetch**，随包本地副本一律直接读——离线也装得上。
* **哈希校验**：下载后核对索引里声明的 `bytes` 与 `sha256`，任一不符**拒收并删临时文件**
  （临时文件走 `pet_io.atomic_write_bytes`，落在 `plugins/_download/`，失败连新建的空目录一起撤）。
  解包前**再**走 `pet_plugin.validate_plugin_zip`（校验器是唯一真源，本模块不写第二套判据）。
* **base_url 口径**：与打包工具 `--base-url` 那套一致——release.url 相对**索引自己所在位置**解析
  （本地索引 → 同目录的 `packs/x.zip` = 随包副本；远端索引 → `https://…/packs/x.zip`），
  绝对 http(s) 原样用。两处共用同一个 `resolve_url`。
* **版本门**：`pet_plugin.version_key`（四段整数，与 `_check_release._ver_key` 同款）；
  `host_min` / `min_host_version` 高于宿主的条目**留在列表里**并给出人话原因，**不静默隐藏**；
  索引 `index_version` 太新 / 结构不对**整份拒绝**（fail-closed，不许当成"没有新版本"）。

### A2 市场页（`PluginManagerDialog` 扩充）
* 两个页签：**已安装**（原六列原样保留）/ **可安装**（插件 / 名称 / 类型 / 大小 / 版本 /
  是否已装 / 可否安装 七列）。
* 动作：安装（索引条目没装过时可用，带**进度条 + 阶段提示 + 可读错误**）、更新（**有新版本时才出现**）、
  回滚（**选中项有上一版时才出现**）、卸载、启用禁用、刷新索引。
* **网络不卡界面**：远端索引与包的取数在后台 daemon 线程里做，结果用 Qt 信号交回主线程槽；
  同一时刻**只有一个在途请求**（`_index_active` / `_pack_active` 代次），在途期间再点只排队一次；
  旧代迟到结果丢弃并记日志；**落地永远在主线程**（宿主库 / 安装登记不跨线程写）——照 `pet_balance`
  的代次/守卫口径，没有自创。**打开对话框不自动联网**（远端要用户点「刷新索引」或切页签）。
* 尺寸：设计尺寸 **760x520 → 860x560**，三处同步（源码 `clamp_dialog` 字面量 /
  `tests/test_dialog_fit_v250.py` 的 `_DESIGN_SIZES` / `_dev/dialog_size_report.md` 3.1 节，
  ③ 由代理 C 收口，已核对一致）。

### A3 更新 / 回滚 / 合并（`pet_plugin_host.py`）
* **内容指纹**：每个落地类别都算一条内容指纹（lines 按"文本+类别+槽位"、对白按"名字+引用文本"、
  audio/voice_ref 按**文件字节**、behaviors 按行为 dict 规范形、prompt 按"文件名+字节"、
  role 按"角色 dict + 素材内容"）；登记里新增 `landed_fingerprints`（与 `landed` 键平行）。
* **更新 = 按内容指纹去重后合并**：指纹见过的条目不再落，没见过的**真的并进宿主库**
  （旧口径"整包跳过"已废）；`landed` 累积历次落地的 id（回滚差集的依据）。
* **回滚**：更新前把当前目录整棵挪到 `plugins/.prev-<id>/`（真留着上一版 payload），登记里存一份
  上一版记录（`history`，深度 1）；`rollback` = 撤销"当前 landed − 上一版 landed"（**用户自己的
  内容一件不动**）+ 把 `.prev-<id>/` 换回来 + 登记回到上一版那条。回滚后**再更新一次仍然正确**
  （指纹账随记录一起退回上一版）。卸载会连 `.prev-<id>/` 一起删。
* **旧登记补账**：v2.5.1 的登记只有 `landed`、没有指纹 → 更新时用**上一版目录**里的 payload 补一次账，
  照样不重复落地；补不出来才退回"这一版不合并新内容"并在文案里说明。
* **禁用**：行为不变（只改登记、内容不撤、目录不删），但**界面文案与行为对齐**：状态格 tooltip +
  顶部提示行都写明"只改登记、不等于卸载"（"已禁用"三个字本身保持原样，老用例仍钉着它）。

### A4 尺寸三处同步
源码 `clamp_dialog(self, 860, 560)` / `_DESIGN_SIZES["PluginManagerDialog"] = (860, 560)` /
`_dev/dialog_size_report.md` 3.1 节（C 已同步）**三处一致**；"每个可钳制对话框都必须登记"
与"登记类必须真是 `_FitDialog` 子类"两条契约用例都绿。

## 4. 探针抓出的两个真 bug（都补了能真失败的用例）

1. **重复安装把回滚点顶掉**（`test_同一个版本重复安装不顶掉回滚点`）：v1 → v2 → v2 之后，
   第二次装 v2 照旧把当前目录挪进 `.prev-<id>/`，**v1 的备份被覆盖** → 回滚只是"原地不动"，
   用户以为回到了 v1、实际还在 v2。修法：同一版本 + 内容一条不新（`repeat`）时**不换目录、
   也不轮换回滚点**（登记里换成沿用原 history）。
2. **repeat 分支的提交路径把目录换坏**（同一条用例）：第一版修法只跳过了"挪走"，仍然执行
   `os.replace(tmp, target)`，而目标目录还在 → Windows 直接 `WinError 5`，整个更新失败。
   修法：repeat 时跳过整段提交（`tmp` 由 finally 清掉）。

## 6. 没做到 / 有疑问（如实报）

1. **下载没有字节级百分比**：注入的 fetch 契约是 `fetch(url) -> (bytes, err)`（一次给全量），
   进度条按"忙等 + 已下载字节数"显示；只有默认 urllib 实现能给"已下载 / 总长"的百分比
   （`Content-Length` 缺失时仍是忙等）。
2. **UI 层没有真人点击验证**：市场页的安装/更新/回滚都是程序化调用（`install_entry` /
   `rollback_id`）+ offscreen Qt 验证；没有在真机上用鼠标点过。确认框（`_confirm`）在测试里被
   替换成记录器，**没有验证真弹窗的观感**。
3. **回滚只保留一版**（`history` 深度 1）：连续更新两次后只能回到"上一次更新的那一版"，
   不能一路退回最初版本。任务书只要求"保留上一个版本"。
4. **role 类去重不查"那只角色还在不在库里"**：按内容指纹判"装过了"就跳过；用户手动删掉那只
   角色后再更新同一个包不会把它加回来（要加回来请先卸载再装）。prompt / lines 两类补了
   "真的还在吗"的判断（文件/文本被删掉会自动补回来），role / audio / behaviors 没补——
   理由：它们落地时会分配新 id 或新名字，回查成本高，且"不重复落"是这一条更重要的性质。
5. **同一包内**内容完全相同的两条（比如两句一模一样的台词）只会落一条（指纹去重是集合语义），
   与"更新时只落新的"共用同一条规则。
6. **没有真联网验证**：远端索引分支只用假 fetch 覆盖（这是任务书的硬要求），真实 GitHub Release
   的 url 拼接形态（`--base-url https://…/releases/download/vX/`）没有实跑过。
7. **`plugins/README.md` 有一处细节可再精确**（C 的文件，我只报不改）：第 42~45 行说"更新前当前
   插件目录整棵挪到 `.prev-<id>/`"——在"同一版本、内容完全一致的重复安装"这条路径上现在**不挪**
   （正是第 4 节那个 bug 的修法），建议补一句"（同一个版本、内容一致的重复安装不换目录、也不动回滚点）"。

## 7. 已登记、**本轮明确不做**（下一轮）

v2.6.0 第 4 轮找茬 / 兼容审查点出、经裁决**留到下一轮**的（都写在各自的"能真失败"口径上，
不是"忘了"）：

1. **`install_file` 只核 id、不核 `data_kind`**：索引写 `data_kind=lines`、包里其实是 `role` 时，
   「可安装」页显示"台词"，装进去落地的是角色。核 data_kind 要动安装器的"包 vs 索引"判据，
   本轮只保证"id 对不上就拒"。
2. **`history` 在"插件目录被手工删 + 装的是另一个版本"时会白丢一个回滚点**，并在磁盘上留一个
   孤儿 `.prev-<id>/`。修它要区分"目录没了"与"版本真的换了"，属于回滚语义的改动。
3. **同内容文件折叠成一份时，回滚文案说"撤销了 0 项"**——对首次安装也这么说，容易被读成
   "什么都没装"。要改的是文案口径（回滚确实撤销了 0 项**新落地**内容）。
4. **razor 的 `check` 不校验"证据字符串是否真是那段代码"**：构造一个合法键 + 假证据仍能过。
   属可接受的残余（razor 的对象是"代码里的静默 except 有没有归属"，不是"证据是不是原文"），
   但要知道这一点。
5. **`_describe_*` 的金额 / 时长判据只做"是不是有限数"**，不做业务范围校验（负数分钟、
   0 元预算照旧走到确认框——那由工具自己的 handler 拒）。范围校验放这里会让"判据"与
   "业务规则"混在两处。
