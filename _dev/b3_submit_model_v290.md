# B3 · 统一提交模型（契约 + 逐对话框清单 + 主代理裁决）

> **这份文件是补录**：B 在 v2.9.0 第 7 轮把 B3 契约用消息交给主代理，主代理转达给 A 并据以裁决，**但从未落成文件**——兼容审查（`_dev/_compat290/COMPAT_REVIEW_v290.md`）点名了这个缺口。此文件补上，作为**契约的书面记录**。

## 一、规则（R1–R4）

- **R1 面板型 → 保存不关窗**。判据是**可复核的结构性事实**：① 窗内存在 ≥1 处"不关窗就地提交"的入口（`_save(silent=True)` 之类）② 或有"必须在本窗口继续用"的入口（试播/试听/测试/朗读）③ 或窗口本体是**列表 + 就地增删改排序、只有点「保存」才落盘**。
- **R2 表单型 → 保存关窗**：整窗内容是一次填完就走的一组设置，窗内没有就地提交/继续用的入口 → 关窗就是"完成"信号。
- **R3 任务型 → 关窗**：按钮不是「保存」而是动作本身（「导入」「确定」「导出」），动作完成即结束，**不算"保存即关窗"**。
- **R4 不变量**：**「保存」永不含糊；丢弃未保存编辑的按钮不许叫「关闭」（该叫「取消」），只关窗不丢编辑的按钮不许叫「取消」（该叫「关闭」）。**

## 三、⚠ 已知未消解（兼容审查实测，2026-10-16）

- **#12 统一提交模型只完成了 #4 一处** → 实测**仍是 6 关窗 vs 3 不关窗**（原 7:2）→ **方向反转而非消解**。下一轮要么按本清单把剩下的收口，要么**明确接受"不统一"并说明理由**。
- **R4 有两处反例（且与本轮改动无关，是遗留）**：
  - `pet_dialogs.py:3652` **`AlarmDialog`** `("删除", self._delete), ("关闭", self.accept)):` —— `_save`(3740-3766) 不关窗、**有暂存态** `_pending_ringtone`(3611)；实测：填草稿→点「关闭」→窗口消失、`alarms 0→0`、**无任何确认**（HEAD 同结果）。
  - `pet_dialogs.py:5090` **台词设置**「关闭」→`accept` 会丢 `_text` 草稿。
  - 另三处 `关闭→reject`（4740/4829/7359）**没有暂存态，不是反例**。
  → **本轮已要求 A 按 R4 修这两处**（丢弃编辑的按钮改叫「取消」+ 按 A5 同口径加未保存确认；**没有改动就直接关**）。

**一条 P0 陷阱（未来动 #6 时的强制前置）**：`RoleEditDialog._save` 只把"没被引用的"从 `_staged` 摘掉，而 `closeEvent`(:2563-2567) 在 `result()!=Accepted` 时 `_cleanup_staged()` **把 `_staged` 全删**——今天不触发**只因为 `_save` 末尾自己 `accept()`**。**一旦把它的「保存」改成不关窗，用户保存成功后点取消走人 → 刚保存进 `roles.json` 的帧文件被删掉。** 改它必须同时：`_save` 成功收尾处 `self._staged = []`，并把 `self._role` 刷成 `self._lib.get(self._role_id)`。
