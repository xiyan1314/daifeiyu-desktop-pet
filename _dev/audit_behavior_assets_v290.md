## A. 「导入素材创建新行为」这条路，逐条判定

**用户想做的事**：把一张/一组图片或一段音频交给桌宠 → 它变成一个**新行为**（能播、能进待机、能分享）。

### A.0 先定义清楚：“行为”里到底能放什么

```
pet_behaviors.BEHAVIOR_ACTS（pet_behaviors.py:47-48）=
  play_action(动作名) · say(台词) · voice(5 个固定事件) · emote(4 种表情)
  form(形态键) · sleep · wait(毫秒) · speak_line(台词 id) · speak_dialogue(对白 id)
```

**结论：9 种步骤里没有任何一种能直接引用“素材”**——图片必须先变成“角色动作”、音频只能绑到 5 个固定事件之一。这是 A 节所有断路的**共同上游**。

### E.3 判断：该不该扩建为统一素材管理？

**该扩建，但只扩建一块；不该做“统一素材中心”重构。** 理由：

- **是功能缺失（该补）**：① **动作没有可见清单**（行为设置里选不到、资源管理里看不到）② **默认角色不能加动作且不说明** ③ **素材 → 行为的引用关系没有任何 UI**。这三条都是“用户想做的事做不到”，不是“难用”。
- **是重构（不该现在做）**：把 `lines` / `behaviors` / 人设搬进资源管理，会**再造**一批“同一功能两个入口”——正是 B/D 节批评的病。而且这三个库各有成熟专属对话框（台词设置 / 行为设置 / AI 设置），搬迁收益是“看起来整齐”，代价是双倍入口与双倍回归面。
- **该冻结**：`assets/`（默认角色素材）保持只读随包；食物图标保持程序化。给它们开编辑口 ＝ 把“发行素材”和“用户素材”混成一锅。

### E.4 最小可行方案（先做什么 / 不做什么）

**先做（都在 v2.9.0 射程内，且都能真失败）**

1. **行为步骤的“动作”参数：自由文本 → 可选可输入的下拉**。数据源 = `pet.custom_actions()`（当前角色当前形态）∪ `pet_resources.ANIM_ACTIONS`（内建 4 个）∪ `jump/emote`，**保留“✎ 手填”一项**（不破坏既有用例）。—— 这一步就把 P1 / P2 / P2b / P2c 四条断路一次接通。
2. **行为设置里加「＋导入图片做动作…」**：把 `RoleEditDialog._add_frame_action` 的实现抽成模块级函数，两个入口共用；按钮旁明写“会加在**角色「X」· 形态「Y」**上（不是加到行为库）”，加完给回执。
3. **「导入…」改名「导入行为文件（.json）…」**，并在选到非 `.json` 时就地给人话（不要落到 `svc.import_file` 去抛英文 codec 异常）。
4. **资源管理加第 4 个页签「动作」**：只读列表 +「删除」+「定位到所属角色」——列 `角色 → 形态 → 动作（帧 N 张 / 合成 类型·幅度·周期）`。**不新建库、不搬数据**，纯视图。
5. 「待机行为」下拉与待机设置二选一（见下一轮清单 #5）。
6. 行为步骤补上移/下移；删除行为时同步清 `idle_actions`。

**不做（明确写下来）**

- ❌ 不把 `lines` / `behaviors` / `prompts` 搬进资源管理（会再造重复入口）。
- ❌ 不新建“统一素材注册表”（`pet_asset_registry` 一类）——6 个库的归一化口径已在各自模块里（`pet_resources.py` 的 `_norm_*`、`pet_behaviors._norm_*`），再包一层只会分叉。
- ❌ 不给 `assets/` 与食物图标开编辑口。
- ❌ 不动 `音效` / `声音素材` 两个库的合并（那是产品决策，见清单 #17）。

## 结论：行为设置到底“哪里不对”

**它不是“按钮坏了”，也不是“反馈没做”——是“选动作”这一步根本没有被设计成一条路：**

> **在“行为设置”里，用户能做的只有“手打一个动作名”；而“从素材做出一个动作”这件事被放在另一个对话框（角色编辑）里，两处之间没有任何指路、没有任何清单、没有任何校验。** 再叠上三件“看着像坏了”的事——①「导入…」只认 `.json` 且选错文件给英文异常 ② 同一个窗口里混着三种提交语义（SpinBox 改一下就落盘 / 表单要按「保存」/「关闭」静默丢草稿）③「待机行为」下拉显示“不启用”而配置里其实有 2 条、点一下就覆盖掉——用户看到的就是「导入素材创建新行为这条路不存在，而且按钮还多余」。

**修法不是再加按钮，而是把这条路补齐**：动作改成可选可输入的下拉 + 在行为设置里就地放一个「导入图片做动作」入口（复用角色编辑那套实现）+ 把「导入…」的语义写清楚。这三件都在 v2.9.0 射程内，且每条都能写出“现树必红”的验收。
