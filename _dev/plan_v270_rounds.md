## 一、五条设计原则（先定原则，再排轮次）

这两份方案都是**方向清单**，不是**时间表**。直接按它们的波次排会撞上三件事：动效各写各的时长（后面统一要返工）、把人的手感当成可排期的活、以及把"低成本高合规价值"的项排到最后。所以先用 HCI 定五条原则，用它来裁剪。

### 原则 1 · 反馈时延预算（分层，不是"越快越好"）
- **本地即时反馈 ≤ 100ms**：点击、按下、悬停起始。超过 100ms 人就会觉得"没反应"——这正是上一轮我们要消灭的那类问题（点了像没效果）。
- **状态过渡 150–250ms**：气泡出现/消失、面板展开、禁用状态切换。
- **位移与大幅变化 300ms**：贴边吸附、窗口移动、位置跳转。
- **> 1s 的操作必须有进度或骨架反馈**：余额查询、AI 对话、角色导入、备份/恢复。
依据：Spectrum UI（反馈 <100ms 才"即时"、状态切换 150–250ms、大幅移动 300ms）· UX Clarity（动画 200–500ms）· WellWorks（骨架屏）。

### 原则 2 · 克制（约束才是高级感）
桌宠是**常驻桌面**的，不是每次交互才出现的界面。**鼠标路过不是交互意图**——每次路过都缩放/发光，会变成视觉噪声。
因此：**悬停类反馈要带停留阈值**（200–300ms 后才触发，且只做"低幅度"的一种：光晕，不做缩放）；**同一时刻只允许一个动效在主角身上**；动效总预算设上限。
依据：UX Clarity「不要过度」· 数字伴侣桌宠「零打扰、悬停 3 秒才互动」· Spectrum UI「约束是高级感」。

### 原则 3 · 动效令牌化 + 可关闭（**必须在第一批动效就建立**）
18 条 UX 项如果各写各的时长与曲线，第 5 条做完就开始互相打架。所以第 7 轮**第一件事**是建 `pet_motion.py`（动效令牌：时长/曲线/幅度常量 + 统一入口），**并同时提供「减少动效」开关**（无障碍 + 低配机 + 用户不喜欢时一键静音）。之后所有动效只准引用令牌，不准写魔法数字。
依据：mujikeer「100–150ms 微动画、可预测运动、8px 网格」· WCAG（动画可关闭/可减少）· 本项目教训（同一个 `_toast`/`_save_failed` 各写一遍就会不一致——v2.7.0 就是靠"统一反馈出口"才收住的）。

### 原则 4 · 可预期（同语义同表现）
同一个语义（"成功"/"失败"/"被拒绝"）在桌宠、气泡、菜单、对话框里必须**同一种表现方式与同一种时长**。随机化只允许出现在**内容**（挑哪句台词/哪个动作），不允许出现在**反馈形式**上。
依据：mujikeer「可预测运动」· Nielsen 一致性启发式。

### 原则 5 · 错误 = 问题 + 可操作建议；无障碍不是可选项
错误提示一律「**发生了什么 + 你现在可以做什么**」。键盘可达、焦点可见、对比度 ≥ 4.5:1、动效可减少——这些**越晚做返工越贵**，所以和动效令牌同轮落地，不排到最后。
依据：UX Clarity「错误提示要具体可操作」· WCAG 2.1（对比度 4.5:1、键盘可达）。

## 二、我对两份方案的修正（12 条，逐条给理由）

这是本计划里最要紧的一节：**不是照抄波次，而是用 HCI 与项目实际去改它们**。

| # | 方案原文 | 我的裁决 | 理由（HCI / 项目实际） |
|---|---|---|---|
| 1 | B3 单双击用 **150ms 延迟**区分 | **不做延迟**，改为：单击**立即**响应；双击由 Qt 的 `mouseDoubleClickEvent` 触发**不同**的动作/台词 | poke 是**主操作**。给主操作加 150ms 人为延迟，直接违反原则 1（<100ms），手感会"变钝"。而"双击多给一个反应"本身不需要抑制单击——连击时先有一次 poke 反而符合直觉。**方案里的这条是为了解决"双击触发两次 poke"，但那样解决是把成本转嫁给每一次单击。**　→ **落轮：第 7 轮**（§7.5-L1；「不做 150ms 延迟」≠「不做」）。|
| 2 | A1 悬停**放大 1.05 + 光晕** | 改为：**停留 200ms 后只做光晕**（不缩放）；缩放置于令牌里作为可选 | 桌宠常驻桌面，鼠标频繁路过（原则 2）。且缩放要穿过现有 `_apply_transform` 与物理管线（`_physics_drag_move`/贴边/root motion），**与物理耦合是真实回归风险**；光晕是纯绘制层，零耦合 |
| 3 | A2 按下 `scale(0.97)` **叠加**现有压扁 | 保留压扁，**只补 100ms 内的高亮描边**；scale 作为令牌可选，不默认叠加 | 现在已有压扁反馈，再叠一层缩放属于过度动效（原则 2）。缺的是"**100ms 内的即时确认**"，那是描边/脉冲的活，不是再变形的活 |
| 4 | A3 点击脉冲圈（Material Ripple） | **采纳**，但限定：半径上限 + 起始不透明度 ≤ 0.5 + 必须跟随角色当前位置 | 涟漪是"点击"的通用语义，值得做；但桌宠是**无边框透明置顶窗口**，涟漪要保证不进任务栏、不遮挡交互、多屏夹紧（复用气泡已有的屏幕夹紧逻辑） |
| 5 | A7 触屏震动反馈 | **不做**（2026-10-15 清单完整性核对改判；原判「押后到长期」作废） | 桌面场景触屏占比低；Win32 触觉 API 不可靠；**鼠标场景根本无法呈现**——做了也验证不了（我们无法自动化验证「震感」）。**长期批（13–16 轮）同样无法验证它**，所以「押后」等于永远挂着，改为明确不做（§7.5-L3） |
| 6 | F1 键盘无障碍 + 高对比度排**最后一波** | **提到第 7 轮**（与动效令牌同轮） | 两者都是**全局设置层**：令牌决定"动多少"，无障碍决定"能不能关/看得清"。分开做就要两次改同一批样式与配置。且合规项越晚越贵　**（含高对比度：方向 3 的「无障碍/高对比度」部分并入此处，只做一次——第 8 轮不再重复，§7.5-L15）** |
| 7 | 18 条各写自己的时长/曲线 | **先建动效令牌表**，再逐条接 | 见原则 3。这是我对两份方案**最重要的补充** |
| 8 | D2 菜单悬停即预览动作 | **采纳但加阈值**：悬停 300ms 后才预览 + 可关闭 | 悬停即播会干扰浏览菜单（原则 2）；且要"预览模式"（不落声音、不改状态、不计入行为统计）　→ **落轮：第 8 轮**（§7.5-L2，含 300ms 停留阈值 + 可关闭 + 预览模式）。|
| 9 | 方向 3「持续气泡」与 A4「气泡淡入淡出」 | **合并到同一轮**（同一个 `Bubble` 类） | 两次改同一个类 = 两次回归风险 + 两次审查。**同模块的活必须同轮** |
| 10 | 方向 4「全屏自动隐藏」与方向 16「窗口吸附/攀爬」 | **先抽 `pet_windows.py`**（前台窗口查询子系统），两轮共用 | 两处都要"知道前台窗口的矩形与状态"。各写一套必然分叉（这类"同一事实两个来源"是本项目已踩过的坑） |
| 11 | 方向 15「屏幕观察 + 主动评论」默认可用 | **必须默认关闭**：显式授权 + 可见指示（宠物身上/托盘上有"正在看"标识）+ 一键暂停 + 应用黑白名单 + 截图只在内存、**不落盘** | 这是**截屏级隐私**。默认开启等于把用户屏幕交给第三方模型。方案自己也写了"隐私敏感"，我要把它升级为**硬约束**，并写进发布说明 |
| 12 | 新依赖（`pygetwindow` / `keyboard` / `live2d-py`）随用随加 | **每加一个依赖都要过一遍发布门**：锁版本 + PyInstaller spec excludes + **误报复评** + 体积对照 | 方案 5.4 已点到误报风险。本项目已有打包与发布门（41 个同步文件 / 150 个素材 / 体积对照），依赖变化必须进门的检查项 |

另外两条**方案没提、但会卡住进度**的实际约束：

- **素材供给**：方向 1（走路帧集）、方向 16（攀爬帧集）、方向 13（AI 生成帧）都需要**新的美术素材**。没有素材，代码做完也看不到效果。→ **必须在对应轮开始前先确认素材**（见第五节卡点）。
- **手感类调参无法排期**：像"悬停幅度多大才舒服""气泡淡入 180ms 还是 220ms"这种，靠人反复试。我们的流水线（实现→三审→验收）**替代不了手感**。→ 所以本计划**把主观项一律换算成可验证的预算**（时长进令牌、幅度有上限、可由"减少动效"关闭），并用**截图/时序断言**做证据，而不是说"感觉更好了"。

## 四、每轮的固定流水（老规矩，不因主题改变）

1. **冻结 + 起草**：写本轮任务书（含领地划分、统一口径、验收标准）
2. **并行实现**：3–5 路，领地互斥（一人一块地）
3. **三审**：找茬 / 质量 / 兼容，**在冻结修订上审**（哈希抄进报告，发现树在动就停手）
4. **修复**：所有发现逐条修，**每条配能真失败的用例**（变异：还原修复必须红，贴原文）
5. **独立验收**：**不是**写代码的人，逐条核 + 牙齿检查 + `git diff HEAD -- tests/` 逐行查有没有放宽断言/删用例/加 skip
6. **全门**：pytest · `_verify_v13.py` · `_check_static.py` · 时间轴 · 关键端到端（**主代理亲自跑，不看代理自述**）
