## 六、补充教训（2026-10-15 实测第二次踩）：**"资源空出来" ≠ "对方承诺不动"**

**事件**：C 报「锁已放，A 可以跑全量」→ 我把它当放行信号转给 A → **约 15 秒后 C 又开了下一个 spec**（提前跑了它说"要等"的那批）。A 的 PRE 检查抓到，**在跑任何 python 之前中断**，**没有产生争用下的数字**。

**定性**：**「锁已放」是状态（瞬时、会过期）；「我已停，等你」是承诺（在我说完之前我不动）。协调必须用承诺，不能用状态。**

**标准协议（已采纳）**：
1. 占用方跑完当前单元 → **停住，不开下一个**；
2. 占用方**明确说「我已停，等你」**；
3. 我把这句**原样转给等待方**；
4. 等待方立刻跑（有时间上限），**第一时间回报**；
5. 我确认结果后，才让占用方继续。

**我自己的错**：我是协调者，**"状态"与"承诺"的区别该由我把关**——我把 C 的状态当承诺转达了。**以后凡放行信号，一律要求承诺措辞。**
## 七、补充教训（2026-10-15 第三次）：**"我照抄一遍"本身就是风险点**

**事件**：我把 A 的第二批 15 条转给 C 时，**手抄了 nodeid**，把 `test_test_play_plays_and_does_not_say_saved_twice` 写成 `test_test_plays_and_does_not_say_saved_twice`（少一个 `play_`）。**如果 C 没跑 `check_mutation_nodeids.py`，这条会以 node-not-found 收场、永远判不成 CAUGHT。**

**规则（追加）**：**转述变异原料时，nodeid 也不许手抄** —— 要么让来源方**写成文件**（文件通道），要么由收方**用工具复核**。**"照抄"看起来最安全，实际是三处风险里最隐蔽的一处。**

## 十二、容量纪律（**用户 2026-10-16 定的新规矩**）

**用户原话**：「**开始下一轮任务时你也要开始新一轮保证上下文足够**」。

**规矩**：**每开一个新轮次，协调者（主代理）必须换新上下文，不许带着耗尽的状态开工。轮次边界 = 上下文边界。**

### 为什么（用第 9 轮的代价换来的）
上下文耗尽的协调者会**可测量地退化**，而**退化会把错误写进仓库**：
1. **只会转达、不再核实** —— 后期我的回合几乎全是"给 A/B/C 发消息"，**自己不再读长输出、不再独立跑门**；
2. **低级错误频发** —— 第 9 轮我犯了 **8 次括号/引号类错误**（漏闭合花括号、ASCII 引号截断 JS 字符串、拿测试解析后的 `0/388` 当文件原文……），**越到后面越频繁**；
3. **自欺** —— 我**一边说"上下文已用尽"、一边继续派活与裁决**（正是用户几轮前警告的"你容易自己骗自己"）。

### 怎么做
1. **每轮收尾时写"自包含交接"**：含**下一步的精确次序**与**硬约束清单**（让新上下文不必翻旧账）；
2. **新上下文开工第一件事：读交接 + 纪律文件 + 本轮任务书**，**读完再动手**；
3. **协调者不要在同一个上下文里连做两轮**（哪怕上一轮"看起来快完了"）；
4. **实现代理同理**：轮次边界换人/换上下文，**交接里写清"我做到哪、下一步是什么、什么不能碰"**。

### 怎么知道自己该换了（**任一出现就收尾交接**）
- **"转达"多于"自产"**（整轮都在转发别人的结论，自己没跑过一次门、没读过一次长输出）；
- **同一类低级错误出现第二次**（例如引号错、路径拍平、拿二手表示当原文）；
- **说不清自己上一步读了什么**（复述不出自己刚做的判断依据）。

**一条配套要求**：**交接里必须包含"未验证的假设"**（哪些是实测、哪些是代理自述未复核）—— 否则新上下文会把上一轮的"未核实"当成事实继承。
